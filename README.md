# Поиск по докладам

Сайт, на котором можно найти, **на каком слайде какого доклада** говорится о нужной теме.
Вводите одно-два слова — и сразу, прямо во время набора, видите ответ: доклад, номер слайда и
предложение с подсвеченными словами.

Поиск понимает:

- **разные формы слов**: «кредит» найдёт «кредитов», «кредитования»;
- **опечатки и неполные слова**: «урбанизацыя», «урбан»;
- **близкие по смыслу слова**: «банкротство» найдёт «несостоятельность» и «невозврат долга»,
  «налоги» — «пошлины», «дань», «тариф».

Сайт бесплатный, работает без сервера и без регистрации, открывается и на телефоне.

**Ссылка на сайт:** `https://ВАШ-ЛОГИН.github.io/НАЗВАНИЕ-РЕПОЗИТОРИЯ/`
(например, для логина `masha` и репозитория `doklady` — `https://masha.github.io/doklady/`).
Точная ссылка появится в репозитории: **Settings → Pages**, вверху страницы.

Ссылку на конкретный поиск можно скопировать из адресной строки и отправить однокурснику:
например, `…/?q=банкротство` сразу откроет поиск по слову «банкротство».

## Первый запуск (один раз)

1. Загрузите все файлы проекта в репозиторий на GitHub (см. ниже, если репозитория ещё нет).
2. Откройте репозиторий на GitHub → вкладка **Settings** → слева **Pages**.
3. В блоке **Build and deployment** в поле **Source** выберите **GitHub Actions**.
4. Откройте вкладку **Actions**, слева выберите **«Собрать и опубликовать сайт»** и нажмите
   **Run workflow** → **Run workflow**. Через 5–10 минут сайт будет доступен по ссылке выше.

Дальше сайт обновляется сам каждый раз, когда вы что-то меняете в репозитории.

### Если репозитория ещё нет

1. На github.com нажмите **+** (вверху справа) → **New repository**, придумайте название
   (например, `doklady`), выберите **Public** и нажмите **Create repository**.
2. На странице нового репозитория нажмите ссылку **uploading an existing file**.
3. Перетащите в окно **содержимое** папки проекта — все файлы и папки, **кроме**
   `node_modules`, `_site`, `_site-test`, `.cache`, `test-results` (если они есть).
   Обязательно должны попасть папки `.github`, `build`, `data`, `presentations`, `site`, `tests`
   и файлы `package.json`, `package-lock.json`, `.gitignore`, `README.md`.
4. Внизу нажмите **Commit changes**.

> Бесплатный GitHub Pages работает только для **публичных** репозиториев. Это значит, что файлы
> докладов будут видны всем, у кого есть ссылка.

## Как добавить презентацию

1. Откройте в репозитории папку **`presentations`**.
2. Нажмите **Add file → Upload files** и перетащите файлы. Подходят **PDF** (лучше всего),
   **PPTX** и **DOCX**. Можно сразу несколько.
3. Нажмите **Commit changes**.
4. Подождите 3–10 минут. За ходом сборки можно следить во вкладке **Actions**:
   жёлтый кружок — идёт сборка, зелёная галочка — сайт обновлён, красный крестик — ошибка
   (см. «Что делать, если сборка упала»).

Советы:

- **PDF — лучший вариант**: из него получаются и точный текст, и картинки слайдов.
  PowerPoint: **Файл → Экспорт → PDF**.
- Название доклада и автор берутся с **первого слайда** (строка вида «Автор: …», «Выполнила: …»,
  «Подготовил: …»). Если на сайте они определились неправильно, исправьте их в файле
  `data/doklady.txt` (инструкция внутри файла).
- Если на слайде только картинка с текстом (скриншот, скан), текст распознаётся автоматически.
- Чтобы **удалить** доклад: откройте файл в папке `presentations` → кнопка **⋯** (вверху справа) →
  **Delete file** → **Commit changes**.
- Чтобы **заменить** доклад новой версией: загрузите файл с тем же именем — старый заменится.
- В папке уже лежит пример `Пример — Банковское дело в Российской империи.pdf`.
  Когда загрузите настоящие доклады, удалите его.

## Как дописать синонимы

Словарь близких по смыслу слов лежит в файле **`data/synonyms.txt`**.

1. Откройте файл на GitHub и нажмите на значок карандаша ✏️ (**Edit this file**).
2. Допишите строку: слова одной группы через запятую, например
   `реформа, преобразование, модернизация`.
   Можно писать словосочетания: `невозврат долга`. Форма слова не важна, но лучше начальная
   («налог», а не «налогами»).
3. Нажмите **Commit changes**. Через несколько минут поиск начнёт учитывать новые слова.

Строки, которые начинаются с `#`, — комментарии. Совпадения по синонимам показываются ниже
точных совпадений и подсвечиваются зелёным.

## Что делать, если сборка упала

1. Откройте вкладку **Actions** и нажмите на запуск с красным крестиком.
2. Нажмите на шаг с крестиком и прочитайте последние строки.

| Что написано | Что сделать |
| --- | --- |
| Ошибка на шаге **«Опубликовать на GitHub Pages»**, упоминается Pages | Проверьте, что в **Settings → Pages → Source** выбрано **GitHub Actions**. Потом в запуске нажмите **Re-run jobs**. |
| Ошибки сети: `fetch failed`, `ETIMEDOUT`, `503`, `huggingface` | Временная проблема с интернетом у GitHub. Нажмите **Re-run jobs** → **Re-run failed jobs**. |
| «Не удалось прочитать …» (жёлтое предупреждение, сборка зелёная) | Этот файл пропущен: возможно, он повреждён или защищён паролем. Пересохраните его в PDF и загрузите снова. |
| `npm ci` и что-то про `package-lock.json` | Скорее всего, этот файл не загрузился в репозиторий. Загрузите его из папки проекта. |
| Что-то другое | Нажмите **Re-run jobs**. Если не помогло — скопируйте текст ошибки и спросите того, кто разбирается в программировании (или Claude). |

Пока новая сборка не прошла, на сайте остаётся предыдущая рабочая версия.

## Как это устроено (для любопытных)

- **Сборка** (`build/build.mjs`, запускается в GitHub Actions): читает `presentations/`, для
  каждого слайда PDF/PPTX (и для каждого раздела DOCX, длинные режутся по ~700 символов)
  достаёт заголовок и текст, делает миниатюру WebP шириной 720 px, распознаёт текст на картинках
  через Tesseract (rus+eng), считает векторы для смыслового поиска. Обработанные файлы кэшируются,
  поэтому повторные сборки быстрые.
- **Сайт** (`site/`) — обычные HTML, CSS и JavaScript, без сервера:
  1. *Мгновенный поиск по словам* — [MiniSearch](https://github.com/lucaong/minisearch) с русским
     стеммером Snowball, поиском по началу слова и нечётким поиском для опечаток. Заголовок слайда
     весит больше текста. Отвечает за несколько миллисекунд на каждое нажатие клавиши.
  2. *Словарь синонимов* — `data/synonyms.txt`.
  3. *Смысловой поиск* — модель
     [USER2-small](https://huggingface.co/onnx-community/USER2-small-ONNX) (русская, 33 МБ,
     квантизация q8) через [transformers.js](https://huggingface.co/docs/transformers.js).
     Векторы слайдов считаются при сборке, вектор запроса — в браузере той же моделью.
     Модель загружается в фоне после открытия страницы и сохраняется в кэше браузера;
     пока её нет, работает поиск по словам. Результаты объединяются методом
     Reciprocal Rank Fusion.

### Запуск на своём компьютере

Нужен [Node.js](https://nodejs.org) 20 или новее.

```bash
npm install
npm run build        # собрать сайт из presentations/ в _site/
npm run serve        # открыть http://localhost:4173/
```

Проверки:

```bash
npx playwright install chromium   # один раз
npm test                          # собирает сайт из tests/fixtures и прогоняет автотесты
```

`npm run fixtures` пересоздаёт тестовые доклады в `tests/fixtures`, `npm run check-model` проверяет,
что смысловая модель загружается.
